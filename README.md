# Аренда спецтехники

[![CI](https://github.com/kasariz/equipment-rental/actions/workflows/ci.yml/badge.svg)](https://github.com/kasariz/equipment-rental/actions/workflows/ci.yml)

Веб-приложение для аренды спецтехники с оператором: каталог техники на карте, бронирование по часам
и сменам с подтверждением по телефону, отзывы о владельцах и арендаторах, панель администратора.

**Бэкенд:** FastAPI, SQLAlchemy 2.0 (async), PostgreSQL 16, Alembic, Docker

**Фронтенд:** React, TypeScript, Vite, Tailwind CSS, TanStack Query, React Router, react-hook-form + zod, Яндекс Карты JS API v3

## Запуск (Windows, PowerShell)

Бэкенд, первый терминал:

```powershell
copy .env.example .env
docker compose up -d                  # поднимает PostgreSQL

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

alembic upgrade head                  # создаёт таблицы и справочник категорий
python -m app.scripts.seed            # демо-техника, клиент и заявки (необязательно)
uvicorn app.main:app --reload
```

Фронтенд, второй терминал:

```powershell
cd frontend
copy .env.example .env.local   # и вписать ключ Яндекс Карт
npm install
npm run dev
```

Ключ для карт: [Кабинет разработчика Яндекса](https://developer.tech.yandex.ru), продукт «JavaScript API».
В настройках ключа нужно указать сайты, где он работает (для разработки — `localhost`).
Файл `.env.local` в репозиторий не попадает.

- Сайт: http://localhost:5173 (именно localhost: ключ Яндекс Карт привязан к этому имени)
- Демо-владелец: `owner@demo.ru` / `demo12345`
- Демо-клиент: `client@demo.ru` / `demo12345`
- Документация API: http://127.0.0.1:8000/api/docs
- Проверка работы: http://127.0.0.1:8000/api/health

После изменений в API обновите типы на фронте (бэкенд должен быть запущен): `npm run gen:api`.

## Администратор

Зарегистрироваться администратором через сайт нельзя. Его создаёт команда (или повышает существующий аккаунт):

```powershell
python -m app.scripts.create_admin admin@example.ru
# в Docker:
docker compose -f docker-compose.prod.yml --env-file .env.prod exec backend python -m app.scripts.create_admin admin@example.ru
```

В «Админке» можно насовсем удалять брони, технику, пользователей и отзывы и вести справочник категорий
с шаблонами характеристик.

## Тесты

```powershell
pip install -r requirements-dev.txt
pytest
```

Нужен запущенный PostgreSQL (`docker compose up -d`). Тесты сами создают отдельную базу `rental_test`,
прогоняют на ней все миграции с нуля и проверяют API через HTTP: авторизацию, права доступа, фильтры
каталога, загрузку фото, расчёт цены, жизненный цикл брони, гонки при одновременных запросах
и Telegram-уведомления (с подменённым Bot API). Те же проверки и линтер запускает GitHub Actions на каждый push.

## Весь стек в Docker

```powershell
copy .env.prod.example .env.prod      # заполнить SECRET_KEY и пароль базы
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
docker compose -f docker-compose.prod.yml --env-file .env.prod exec backend python -m app.scripts.seed
```

Сайт откроется на http://localhost. Три контейнера: PostgreSQL, бэкенд (миграции применяются при старте)
и Caddy, который раздаёт собранный фронтенд и фото, проксирует `/api` и на сервере с доменом
сам получает HTTPS-сертификат.

## Уведомления в Telegram (необязательно)

1. Создайте бота у [@BotFather](https://t.me/BotFather) и впишите токен в `.env`: `TELEGRAM_BOT_TOKEN=...`
2. Перезапустите бэкенд.
3. На сайте откройте профиль → «Подключить Telegram» → в боте нажмите «Запустить».

Владелец получает новые заявки с телефоном клиента и отмены, клиент — подтверждения, отказы
и сгоревшие заявки. Без токена сайт работает как обычно, просто ничего не отправляет.

## Как работает бронирование

Клиент выбирает тариф (по часам или посменно), день, время и оставляет заявку с телефоном.
Время сразу резервируется, владелец видит заявку в разделе «Заявки», звонит клиенту
и подтверждает или отклоняет её. Если владелец не подтвердил заявку за сутки или наступило
время начала, она сгорает и время освобождается.

Статусы: `pending` → `confirmed` → `active` → `completed`, а также `cancelled` (отменил клиент),
`rejected` (отклонил владелец) и `expired` (сгорела).

## Архитектурные решения

**Защита от двойного бронирования на уровне БД.** Период аренды хранится как `tstzrange`,
а таблица `bookings` содержит exclusion constraint:

```sql
EXCLUDE USING gist (equipment_id WITH =, period WITH &&)
WHERE (status IN ('pending', 'confirmed', 'active'))
```

PostgreSQL сам не даст сохранить пересекающиеся брони одной техники, даже при одновременных
запросах. Интервалы полуоткрытые `[начало, конец)`, поэтому аренды «встык» (10:00–14:00 и 14:00–18:00)
разрешены, а отменённые и завершённые брони в проверке не участвуют.

**Авторизация через httpOnly-cookie.** JWT хранится в cookie, недоступной из JavaScript, поэтому
XSS не может украсть токен. `SameSite=Lax` защищает от CSRF. В разработке Vite проксирует `/api`
на FastAPI, так что фронт и API работают с одного адреса и CORS не нужен.

**Типы API из OpenAPI.** TypeScript-типы фронтенда генерируются из схемы FastAPI
(`openapi-typescript` + `openapi-fetch`), поэтому изменение контракта API сразу видно при сборке фронта.

**Поиск свободной техники.** Фильтр «свободна в период» использует тот же оператор пересечения
диапазонов `&&` и тот же GiST-индекс, что и ограничение от двойного бронирования.

**Фото.** Загруженные файлы проверяются через Pillow (расширению и Content-Type не доверяем),
уменьшаются до 1600 px и перекодируются в WebP. Заодно из снимков удаляется EXIF с геолокацией.

**Гео-поиск.** Расстояние считается формулой сферических косинусов прямо в SQL. Для каталога
на тысячи единиц этого хватает, при росте план — PostGIS и пространственный индекс.

**Гонки при бронировании.** Свободно ли время, не проверяется отдельным SELECT перед вставкой:
между проверкой и вставкой другой клиент успеет занять слот. Бронь сразу вставляется,
а если сработало ограничение `EXCLUDE` (SQLSTATE 23P01), клиент получает 409 «Это время уже занято».
Смена статуса берёт строку с `SELECT … FOR UPDATE`, поэтому одновременные «Подтвердить» и
«Отменить» не перезапишут друг друга.

**Цена фиксируется в заявке.** Расчёт делает одна функция и для предпросмотра, и для создания
брони. Сумма сохраняется в брони, поэтому смена прайса владельцем не меняет уже оформленные заявки.

**Telegram-бот без библиотек.** Нужны всего несколько методов Bot API, поэтому бот — это
тонкая обёртка над `httpx`. Обновления забираются long polling'ом (публичный адрес не нужен),
аккаунт привязывается по одноразовому коду в ссылке `t.me/<бот>?start=<код>`, который живёт 10 минут.
Уведомления уходят через `BackgroundTasks` после ответа клиенту, так что недоступность Telegram
не ломает бронирование. Если пользователь заблокировал бота, его чат автоматически отвязывается.
Пользовательский текст в сообщениях экранируется: имя «Иван &lt;b&gt;» не сломает разметку.

**Нормализованные адреса.** Адрес техники и доставки выбирается из подсказок HTTP Геокодера Яндекса.
Каждый адрес из геокодера сервер подписывает HMAC-ключом, а при сохранении проверяет подпись — поэтому
произвольный текст не пройдёт и в обход формы. Ключ геокодера хранится только на сервере.

**Телефоны в едином виде.** «8 900 123-45-67», «+7 (900) 123-45-67» и «9001234567» сохраняются как `+79001234567`:
и на фронте (маска ввода), и на бэкенде (проверка в схеме), так что поиск и звонки работают одинаково.
