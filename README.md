# Аренда спецтехники

Веб-приложение для аренды спецтехники: каталог техники на карте, бронирование по часам и сменам,
опционально с оператором и доставкой на объект.

**Бэкенд:** FastAPI, SQLAlchemy 2.0 (async), PostgreSQL 16, Alembic, Docker

**Фронтенд:** React, TypeScript, Vite, Tailwind CSS, TanStack Query, React Router, react-hook-form + zod

## Запуск (Windows, PowerShell)

Бэкенд, первый терминал:

```powershell
copy .env.example .env
docker compose up -d                  # поднимает PostgreSQL

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

alembic upgrade head                  # создаёт таблицы и справочник категорий
python -m app.scripts.seed            # демо-техника, клиент и заявки (необязательно)
uvicorn app.main:app --reload
```

Фронтенд, второй терминал:

```powershell
cd frontend
npm install
npm run dev
```

- Сайт: http://127.0.0.1:5173
- Демо-владелец: `owner@demo.ru` / `demo12345`
- Демо-клиент: `client@demo.ru` / `demo12345`
- Документация API: http://127.0.0.1:8000/docs
- Проверка работы: http://127.0.0.1:8000/api/health

После изменений в API обновите типы на фронте (бэкенд должен быть запущен): `npm run gen:api`.

## Как работает бронирование

Клиент выбирает тариф (по часам или посменно), день, время и оставляет заявку с телефоном.
Время сразу резервируется, владелец видит заявку в разделе «Заявки», звонит клиенту
и подтверждает или отклоняет её. Если владелец не подтвердил заявку за сутки или наступило
время начала, она сгорает и время освобождается.

Статусы: `pending` → `confirmed` → `active` → `completed`, а также `cancelled` (отменил клиент),
`rejected` (отклонил владелец) и `expired` (сгорела).

## Архитектурные решения

**Защита от двойного бронирования на уровне БД.** Период аренды хранится как `tstzrange`,
а таблица `bookings` содержит exclusion constraint:

```sql
EXCLUDE USING gist (equipment_id WITH =, period WITH &&)
WHERE (status IN ('pending', 'confirmed', 'active'))
```

PostgreSQL сам не даст сохранить пересекающиеся брони одной техники, даже при одновременных
запросах. Интервалы полуоткрытые `[начало, конец)`, поэтому аренды «встык» (10:00–14:00 и 14:00–18:00)
разрешены, а отменённые и завершённые брони в проверке не участвуют.

**Авторизация через httpOnly-cookie.** JWT хранится в cookie, недоступной из JavaScript, поэтому
XSS не может украсть токен. `SameSite=Lax` защищает от CSRF. В разработке Vite проксирует `/api`
на FastAPI, так что фронт и API работают с одного адреса и CORS не нужен.

**Типы API из OpenAPI.** TypeScript-типы фронтенда генерируются из схемы FastAPI
(`openapi-typescript` + `openapi-fetch`), поэтому изменение контракта API сразу видно при сборке фронта.

**Поиск свободной техники.** Фильтр «свободна в период» использует тот же оператор пересечения
диапазонов `&&` и тот же GiST-индекс, что и ограничение от двойного бронирования.

**Фото.** Загруженные файлы проверяются через Pillow (расширению и Content-Type не доверяем),
уменьшаются до 1600 px и перекодируются в WebP. Заодно из снимков удаляется EXIF с геолокацией.

**Гео-поиск.** Расстояние считается формулой сферических косинусов прямо в SQL. Для каталога
на тысячи единиц этого хватает, при росте план — PostGIS и пространственный индекс.

**Гонки при бронировании.** Свободно ли время, не проверяется отдельным SELECT перед вставкой:
между проверкой и вставкой другой клиент успеет занять слот. Бронь сразу вставляется,
а если сработало ограничение `EXCLUDE` (SQLSTATE 23P01), клиент получает 409 «Это время уже занято».
Смена статуса берёт строку с `SELECT … FOR UPDATE`, поэтому одновременные «Подтвердить» и
«Отменить» не перезапишут друг друга.

**Цена фиксируется в заявке.** Расчёт делает одна функция и для предпросмотра, и для создания
брони. Сумма сохраняется в брони, поэтому смена прайса владельцем не меняет уже оформленные заявки.
